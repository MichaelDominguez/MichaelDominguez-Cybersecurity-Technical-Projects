# M.D.2 — Port Scanning & System Vulnerability Research
## Nmap Enumeration, Wireshark Scan Signatures, and CVE Review

**Technical Context:** Network Scanning, Traffic Inspection, Service Discovery, and Vulnerability Intelligence

---

## Overview

This project focused on practical network scanning and vulnerability research using Nmap, Zenmap, Wireshark, and public vulnerability-intelligence resources. The goal was to understand how systems are discovered, how open services are identified, how scanning activity appears in packet captures, and how discovered technologies can be researched against known vulnerabilities.

The project connects two important cybersecurity workflows: network discovery and vulnerability analysis. First, network scanning was used to identify hosts and exposed services. Then, vulnerability databases were reviewed to understand how public CVE information, CVSS scoring, and exploit references support risk prioritization.

---

## Objective

- Identify local network configuration before scanning
- Perform host discovery and subnet-wide scanning
- Observe ARP broadcast behavior generated by discovery scans
- Compare TCP Connect scanning with SYN-style scanning behavior
- Inspect scan traffic using Wireshark packet captures
- Research CVEs, CVSS severity scores, and public exploit references
- Understand how vulnerability scanners support remediation prioritization

## Methodology

The assessment was performed from a Windows 10 Enterprise environment using Nmap/Zenmap and Wireshark. Wireshark captured traffic generated during scanning so that the scan behavior could be analyzed from both tool-output and packet-output perspectives.

Representative commands used during the project included:

```bash
ipconfig
nmap -sn [target]
nmap -sn [subnet range]
nmap -sT [gateway]
nmap -sS [gateway]
nmap -O [gateway]
```

Sensitive system identifiers and public IP information were generalized for privacy.

---

## Host Discovery and Ping Sweep Analysis

Nmap host discovery scans were performed against the local network to identify reachable systems. A subnet-wide scan checked 255 possible host addresses and completed in approximately 11.45 seconds.

During this activity, Wireshark captured a significant amount of ARP broadcast traffic. This behavior is expected during local subnet discovery because the scanning workstation must resolve local IP addresses to MAC addresses before communication can occur.

Observed behavior included:

- 255 host addresses scanned during subnet enumeration
- ARP broadcast activity generated by discovery attempts
- Scan traffic originating from the scanning workstation
- Host-status results displayed through Zenmap output

Security relevance: host discovery is an early reconnaissance step used by both administrators and attackers. Defenders can monitor scan signatures, ARP bursts, and unusual sweep behavior to detect unauthorized reconnaissance.

## TCP Connect Scan Analysis

A TCP Connect scan was performed using:

```bash
nmap -sT [gateway]
```

This scanning method attempts to complete the full TCP three-way handshake with target ports. The scan identified 2 open ports and took approximately 50.94 seconds. Wireshark captured approximately 9037 packets during this scan.

The packet capture showed:

- SYN packets sent from the scanning host
- SYN/ACK responses from open ports
- ACK packets completing TCP sessions
- RST/ACK responses associated with closed ports

The following Wireshark filter was used to isolate HTTP-related traffic:

```text
tcp.port == 80
```

Filtering on port 80 allowed the TCP handshake to be reviewed more clearly. This made it possible to distinguish open-port behavior from closed-port responses.

Security relevance: TCP Connect scans are reliable but highly visible because they complete full TCP sessions. This can create detectable logs and packet patterns on monitored networks.

---

## TCP SYN Scan Comparison

A SYN-style scan was performed using:

```bash
nmap -sS [gateway]
```

This scan also identified 2 open ports and completed in approximately 51.18 seconds. Wireshark captured approximately 2951 packets during the activity.

Unlike the full TCP Connect scan, the SYN scan did not complete the full three-way handshake. Instead, the scanner sent SYN packets, received SYN/ACK responses from open ports, and then terminated communication with RST packets.

This comparison demonstrated an important scanning distinction:

- TCP Connect scan: completes the full handshake
- SYN scan: interrupts the connection before full session establishment
- Closed ports: commonly respond with RST/ACK behavior
- Open ports: respond with SYN/ACK behavior

Security relevance: SYN scanning is often used during reconnaissance because it can reduce completed session visibility compared with full TCP Connect scanning. Packet analysis still reveals the scanning pattern.

## Operating System Fingerprinting

Operating system detection was explored using:

```bash
nmap -O [gateway]
```

Nmap attempted to estimate the target operating system by analyzing TCP/IP stack behavior. No exact operating-system match was identified, but the exercise demonstrated how OS fingerprinting uses differences in network-stack implementation to estimate target platform characteristics.

Security relevance: OS fingerprinting helps attackers choose likely exploit paths, but it also helps defenders inventory assets and identify unexpected systems on a network.

## Vulnerability Intelligence Research

The project transitioned from network scanning to vulnerability research using public security-intelligence platforms. The workflow included reviewing vendor vulnerability exposure, CVSS metrics, exploit references, and known Microsoft Windows vulnerabilities.

Platforms reviewed included:

- MITRE CVE Database
- National Vulnerability Database (NVD)
- Rapid7 Vulnerability Database
- CVEDetails
- Exploit-DB
- Microsoft Security Response Center (MSRC)

A specific example reviewed was **CVE-2022-30216**, which included:

- CVSS v3 Base Score: 8.8
- Impact Score: 5.9
- Exploitability Score: 2.8
- Public exploit-reference review through Rapid7-style vulnerability research

The project also reviewed a Microsoft PostScript and PCL6 Class Printer Driver remote code execution vulnerability, showing how publicly disclosed vulnerabilities can map to real-world impact such as remote code execution.

## Security Reconnaissance Workflow

This project demonstrated a realistic vulnerability-assessment workflow:

1. Identify local IP configuration
2. Select valid targets and subnet ranges
3. Perform host discovery
4. Enumerate open ports and services
5. Capture scanning traffic with Wireshark
6. Compare packet signatures between scan types
7. Research public vulnerabilities using CVE/CVSS resources
8. Prioritize risk based on severity and exploitability

This workflow is relevant to entry-level security operations, vulnerability management, and penetration-testing preparation because it links observable network exposure to public vulnerability intelligence.
